> 版本：v1.1
> 平台：Godot 4.x · Android · 局域网多人（队伍人数任意）
> 类型：2D 俯视角休闲竞技 · 物理推挤对战

## 一、游戏概要

| 项目 | 内容 |
|---|---|
| 游戏名（暂定） | 空岛落叶大作战 |
| 引擎 / 平台 | Godot 4.x，Android 端首发 |
| 视角 | 俯视角（Top-down 2D） |
| 联机方式 | 局域网（LAN）多人联机：UDP 广播发现房间 + ENet 传输对局数据 |
| 队伍规模 | 任意（1v1、2v2、1v2 娱乐局均可），大厅内自由分队 |
| 地图尺寸 | 可选：小 / 中 / 大（建房时选择，见 §2.3） |

| 胜负判定 | 倒计时结束，队伍历史累计总金币更高的一方获胜 |

### 核心体验关键词
- **手忙脚乱**：树叶到处飞，人和树叶一起被吹飞
- **损人利己**：吹树叶赚钱，吹对手出局
- **成长滚雪球**：抽奖强化吹风筒，越到后期风越猛

## 二、世界观与场景设定

### 2.1 场景：空岛
- 悬浮于空中的岛屿地图，四周无护栏，**掉落即出局（等待复活）**。
- 地图元素：
  - **落叶**：周期性从空中 / 树上飘落，是核心资源与"弹药"。
  - **落叶洞**：地面上的小型地漏状洞口，是**唯一的得分设施**（详见 §2.2）。

### 2.2 落叶洞（地漏式得分点）
- **外观**：嵌在地表的小圆洞，带格栅 / 旋涡动画，像地漏一样把飘到附近的落叶"吸"进去。
- **归属**：**双方队伍各有一个专属落叶洞**，颜色 / 标识区分（如红洞、蓝洞），位置对称布置在各自半场。
- **吸入判定**：
  - 吸入半径建议 64–96 px（配置化），进入半径的落叶受到指向洞口的引力，螺旋缩小被吸入。
  - 落叶被吸入 = **归属队伍 +1 金币**（每片固定 1 金币，无稀有树叶）。
- **得分规则（重要）**：金币记在**洞的归属队伍**头上，与"是谁吹的"无关。
  - 这意味着把树叶吹进**对方的洞 = 给对面送分**，会产生"帮倒忙"的搞笑 / 失误场面，符合派对游戏调性。
  - 若后续测试发现恶意送分（演员行为）问题严重，可再加"按最后触碰者归属"的备选规则，当前版本按归属制实现。
- **与人无关**：落叶洞不吸入玩家，玩家可安全踩过。

### 2.3 地图尺寸档位
建房时由房主选择，配置化：

| 档位 | 建议人数 | 岛屿直径（参考） | 同屏树叶上限 | 落叶洞位置 |
|---|---|---|---|---|
| 小图 | 2–4 人 | ~1200 px | 300 | 双方半场各 1 个 |
| 中图 | 4–6 人 | ~2000 px | 500 | 双方半场各 1 个 |
| 大图 | 6–10 人 | ~3000 px | 800 | 双方半场各 1 个（大图可考虑每队 2 个，预留配置项） |

> 地图尺寸也决定相机缩放 / 移动范围与树叶生成密度，均走配置表。

## 三、核心玩法循环

```
落叶飘落 → 玩家用吹风筒吹动落叶 → 落叶被吸入己方落叶洞 → +1 金币
                                        ↓
                              个人金币攒够 → 抽奖强化吹风筒
                                        ↓
                    强化后吹得更远/更宽/更狠 → 更高效收集 + 压制对手
                                        ↓
                         倒计时结束 → 比队伍总金币 → 结算
```

### 3.1 玩家道具：吹风筒
玩家唯一常驻道具，**无限使用**（无弹药、无过热、无冷却，按住就吹），两种作用对象：

| 作用对象 | 效果 |
|---|---|
| 落叶 | 施加风力推动，吹向己方落叶洞得分 |
| 其他玩家 | 施加冲击力推动，被吹出空岛边缘即掉落 |

**基础参数（配置化，以下为初始默认值）：**

| 参数 | 默认值 | 说明 |
|---|---|---|
| 风速（对树叶推力） | 800 px/s² | 扇形范围内对树叶施加的加速度 |
| 风力衰减系数 | 0.5 | 风力随距离衰减的比例 |
| 对玩家冲击力 | 400 px/s² | 基础击退强度 |
| 扇形作用角度 | 30° | 出风口锥形范围 |
| 作用距离 | 300 px | 风力最大射程 |
| 使用限制 | **无** | 无限使用 |

> 无限使用下，"对吹"会成为常态对抗手段；对玩家冲击力数值需要在测试中重点调校，避免"谁也吹不动谁"或"一碰就飞"两个极端。

### 3.2 掉落与复活
- 玩家被吹出空岛边界 → 掉落 → 进入复活等待。
- **复活规则（配置化）：**
  - 复活时间：5 秒（随掉落次数递增：+2 秒/次，封顶 15 秒，防止滚雪球压制）
  - 复活点：己方半场固定复活点，复活后 2 秒无敌（防风守尸）
  - 掉落惩罚：不掉金币（金币已全部累计入队伍总分），只损失在场时间

## 四、金币双轨经济系统（核心规则）

务必拆成**两个完全独立的数值**：

### 4.1 队伍总金币（TeamTotalScore）——胜负判定用
- 定义：队伍内所有成员**历史获得金币的累加总和**。
- **只增不减**：抽奖、任何消费行为均不扣减。
- 用途：对局结束以此数值对比，高者胜；顶部 UI 的 winning progress 进度条展示此值。

### 4.2 个人金币（PersonalCoin）——消费用
- 定义：玩家个人通过把树叶吹入己方落叶洞获得的金币（每片 1 金币）。
- **会被消耗**：抽奖时扣除。
- 用途：仅用于抽奖强化，与胜负无直接关系。

> 归属判定细节：树叶进洞时，主机回溯"最后一次对该树叶施加风力的玩家"记为得分者，其个人金币 +1，同时队伍总金币 +1。树叶自由飘落 / 被洞自然吸入（无人吹过）则只加队伍总分、不加个人金币（防挂机蹭钱）。

### 4.3 数据流示例
```
玩家 A 吹 10 片树叶入己方洞（每片 1 金币）
  → 玩家 A 个人金币 +10
  → 队伍总金币 +10（永久累加）

玩家 A 花 50 个人金币抽奖
  → 玩家 A 个人金币 -50
  → 队伍总金币 不变
```

### 4.4 实现要点
- 两个数值都由**主机权威计算**，客户端只展示。
- 金币获取事件结构：`{ leaf_id, scorer_player_id, team_id, amount: 1 }`，服务器分别累加到个人池与队伍池。
- **经济节奏参考**：首次抽奖 50 金币 = 吹入 50 片树叶，按预估收集效率约 1.5–2.5 分钟达成首抽，符合"前中期开始滚雪球"的节奏设计；实测后调整树叶密度或抽奖价格。

## 五、抽奖强化系统

### 5.1 抽奖规则
- 消耗货币：个人金币。
- 价格递增：初始 50，每抽一次递增。**建议线性曲线（配置化）：**
  - `price = 50 + 50 × 已抽次数`（50 / 100 / 150 / 200…）
  - 线性曲线让休闲玩家始终有"再吹几片就能抽"的短目标。
- 个人抽奖次数独立计数（每人价格独立递增），避免队友先抽抬高你的价格。

### 5.2 强化词条表（配置化）

| 词条 | 效果 | 数值建议（每级） | 权重 | 可否重复获得 |
|---|---|---|---|---|
| 加强电机 | 风速提升 | +15% | 30 | 可叠加，上限 5 级 |
| 重塑风形·聚 | 风力衰减减小（风吹更远） | 衰减系数 -20% | 20 | 可叠加，上限 3 级 |
| 重塑风形·散 | 风力衰减增大但近距离更猛 | 近距推力 +25% | 10 | 与"聚"互斥或独立，待平衡 |
| 加入沙子 | 对玩家冲击力提升 | +20% | 25 | 可叠加，上限 5 级 |
| 修改出风口 | 扇形角度扩大 | 30°→45°→60° | 15 | 阶梯式，上限 2 级 |

### 5.3 配置化建议（Godot 实现）
用 `Resource`（自定义 `EnhancementEntry` 资源）驱动词条表：

```gdscript
# 示例：enhancement_entry.gd
class_name EnhancementEntry extends Resource
@export var id: StringName
@export var display_name: String
@export var weight: int              # 抽取权重
@export var max_stack: int           # 叠加上限
@export var value_per_stack: float   # 每级数值
@export var target_stat: StringName  # 作用于哪个属性
```

抽奖逻辑：按权重随机 → 已满级词条从池中剔除 → 全部满级时返还部分金币。

### 5.4 平衡性预留
- 记录每个词条的"被抽次数"用于赛后平衡分析。
- 可选保底：连续 3 次抽到同类型词条后必出不同类型（防脸黑），先留接口。

## 六、大厅与局域网联机系统（重点新增）

### 6.1 整体流程
```
主菜单
 ├─ 创建房间 → 建房设置（房间名 / 地图尺寸 / 每队人数上限可选）→ 进入大厅（自己是房主）
 └─ 加入游戏 → 局域网房间扫描列表 → 选择等待中的房间 → 进入大厅
                                                    └─ 手动输入 IP（兜底）
大厅内：查看玩家列表 → 自由选队 / 换队 → 房主确认开局（或全员准备自动开）
   ↓
对局 → 结算 → 返回大厅（房间保留，可换队 / 换图后再来一局）
```

### 6.2 局域网房间发现（LAN Scanning）
**协议分工：UDP 广播负责"发现"，ENet 负责"对局"。**

- **主机端（建房后启动广播信标）：**
  - 用 `PacketPeerUDP` 每 1 秒向局域网广播地址（`255.255.255.255`，子网严格环境可用 `x.x.x.255`）发送房间信息包，发现端口建议 `47777`（配置化）。
  - Godot 侧需 `set_broadcast_enabled(true)`。
- **广播包内容（JSON 即可）：**

```json
{
  "room_name": "小明的房间",
  "host_ip": "192.168.1.23",
  "game_port": 10567,
  "players": 3,
  "max_players": 8,
  "map_size": "medium",
  "state": "waiting",
  "version": "1.0.0"
}
```

- **客户端（扫描列表）：**
  - 监听发现端口，按 `host_ip` 聚合房间条目，实时刷新人数 / 状态。
  - **超时剔除**：超过 3 秒未收到某房间心跳 → 从列表移除（房主关房 / 掉线自动消失）。
  - **版本校验**：`version` 不一致的房间置灰，提示"版本不同"。
- **房间状态：**
  - `waiting`：大厅等待中，**可加入**（列表中高亮 + "加入"按钮）。
  - `playing`：对局进行中，不可加入（列表置灰，显示"对局中"），对局结束回大厅后自动恢复可加入。
- **兜底方案：**
  - 部分路由器开启 AP 隔离会导致 UDP 广播不可达 → 提供**手动输入 IP 直连**入口。
  - 建议在帮助文案里提示"也可由一名玩家开手机热点，其他人连入后建房"（热点天然是最稳的局域网环境）。

### 6.3 大厅功能
| 功能 | 说明 |
|---|---|
| 玩家列表 | 显示所有已加入玩家（昵称 + 队伍颜色） |
| 自由分队 | 点选加入红队 / 蓝队，人数可任意（允许 1v2 等不平衡局，属娱乐玩法） |
| 地图设置 | 房主专属：切换小 / 中 / 大图，切换即时同步给所有人 |
| 开局规则 | 二选一（配置）：A. 房主点击"开始"；B. 全员"准备"后自动 5 秒倒数开局 |
| 断线处理 | 大厅中掉线直接移除并广播；对局中掉线 10 秒内可重连恢复，超时移除角色（其贡献金币保留在队伍总分） |
| 房主退出 | 房间解散，所有人收到提示返回主菜单（房主迁移不做，超出派对游戏复杂度需求） |

## 七、重点系统设计与风险

### 7.1 ⚠️ 树叶物理性能优化（最高优先级技术风险）

**风险**：同屏树叶 300–800（随地图档位）、运动频繁，若每片使用 `RigidBody2D`，物理引擎开销 + 网络同步开销会直接导致安卓中端机卡顿。

**推荐方案：放弃刚体，自研轻量树叶模拟**

| 优化点 | 具体做法 |
|---|---|
| 不用 RigidBody2D | 树叶用 `Node2D` + 自定义脚本模拟：只存 `position / velocity / angular_velocity`，每帧手动积分（欧拉法足够），不进入 PhysicsServer |
| 风力计算 | 只对"处于某个吹风筒扇形范围内"的树叶施力；扇形角度 + 距离粗判，避免全图遍历 |
| 落叶洞引力 | 同理，只查洞口半径内的树叶施加吸入引力 |
| 分块空间管理 | 地图划网格（如 128×128 px cell），树叶按 cell 注册，受力 / 吸入查询只查相关 cell |
| 分帧更新 | 树叶分 4–8 组，每帧只更新一组逻辑（视觉插值保持 60fps），模拟等效 15–30Hz 足够 |
| 休眠机制 | 静止超 1 秒且不受力的树叶休眠，跳过更新；受力唤醒 |
| 渲染合批 | `MultiMeshInstance2D` 一次 draw call 渲染全部树叶，不用几百个 Sprite2D 节点 |
| 对象池 | 被吸入 / 出界的树叶回收复用，避免频繁 instantiate/free 造成 GC 峰值 |
| 简化碰撞 | 树叶与地形只做"落地即停"判定，树叶之间**不做**相互碰撞（视觉允许穿叠） |

**目标指标**：中端安卓机（骁龙 7 系 / 天玑 8000 级）中图 500 树叶稳定 60fps；低端机降配到小图 300 树叶 + 30Hz 模拟。

### 7.2 对局同步方案（主机权威）

| 同步对象 | 同步策略 | 频率建议 |
|---|---|---|
| 玩家位置 / 状态 | 主机权威 + 客户端插值预测 | 20–30 Hz |
| 金币数值 | 主机计算，变化时广播 | 事件触发 |
| 抽奖结果 | 主机随机，广播结果（防作弊） | 事件触发 |
| 树叶 | **不同步每片实时位置**——主机广播"风力事件"，各端本地模拟，低频（1–2 Hz）校正关键树叶；**入洞判定以主机为准** | 事件 + 低频校正 |
| 大厅状态 | 分队 / 地图 / 准备状态变更即广播 | 事件触发 |

> 树叶同步是第二大网络风险。几百片树叶逐帧同步会打爆带宽，必须走"事件同步 + 本地模拟"路线。

## 八、时装系统（预留，最低优先级）

- **定位**：纯外观，不影响数值，时间充裕才开发。
- **最小可行方案（MVP）**：角色换色 / 换贴图 + 吹风筒皮肤，`SpriteFrames` 资源替换即可。
- **扩展方向**：帽子、尾迹特效、树叶入洞特效皮肤、胜利动作。
- **决策节点**：核心玩法 + 抽奖 + 结算全部完成并通过联机测试后，再评估剩余时间决定是否开工。

## 九、对局流程状态机

```
主菜单
  ├─ 创建房间（选地图尺寸）────────┐
  └─ 扫描局域网房间 → 加入 waiting 房间 ┘
                ↓
        大厅（选队 / 换图 / 准备，房间广播状态 = waiting）
                ↓ 房主开始 / 全员准备
        房间锁定（广播状态 = playing）→ 载入地图 → 3-2-1
                ↓
        对局中（落叶生成 / 吹风 / 抽奖 / 掉落复活循环）
                ↓ 倒计时归零
        锁分（停止判定，等网络数据收敛 ~1 秒）
                ↓
        结算（总分对比 → 胜负动画 → 统计）
                ↓
        返回大厅（房间状态恢复 waiting，可再来一局）
```

## 十、开发里程碑建议

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| M1 核心手感 | 单机版：移动 + 吹风 + 树叶轻量模拟 + 落叶洞吸入判定 | 单机吹树叶入洞流畅，500 树叶不卡 |
| M2 联机与大厅 | UDP 房间扫描、建房 / 加入、大厅分队、玩家同步、金币双轨 | 双机互相发现房间并完整对局，金币计算正确 |
| M3 玩法闭环 | 抽奖系统、掉落复活、倒计时结算 | 完整打完一局并正确判胜负 |
| M4 UI 完善 | 主菜单 / 扫描列表 / 大厅 / 抽奖 / 结算全套 UI | 全部 UI 可用 |
| M5 优化打磨 | 树叶性能压测、网络同步优化、平衡调整、AP 隔离兜底验证 | 中端安卓联机稳定 60fps |
| M6（可选） | 时装系统 MVP | 换色/皮肤可用 |

## 附录 A：建议的目录结构（Godot）

```
project/
├── scenes/
│   ├── main/           # 主菜单、房间扫描列表
│   ├── lobby/          # 大厅（分队、地图设置）
│   ├── game/           # 对局场景、空岛地图（小/中/大）

│   ├── leaves/         # 树叶管理器（对象池、MultiMesh）、落叶洞
│   └── ui/             # 对局内 UI（顶部栏、抽奖、结算）
├── scripts/
│   ├── net/
│   │   ├── discovery/  # UDP 广播信标 + 房间扫描
│   │   └── session/    # ENet 会话、同步逻辑
│   ├── economy/        # 金币双轨系统
│   ├── gacha/          # 抽奖系统
│   └── config/         # 配置加载
├── resources/
│   ├── enhancements/   # 强化词条 .tres 配置
│   ├── maps/           # 地图档位配置
│   └── balance/        # 数值配置表
└── assets/
```
